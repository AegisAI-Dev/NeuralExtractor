# Neural Extractor V3.0.8

Build label: `pyside-provider-free-local-audit`

Windows x64. Unsigned executable: Windows SmartScreen may warn on first run.

## What this release fixes

- Fixes exact verified Chrome/Firefox provider selection, so a download uses
  the specific browser session that most recently completed verification
  instead of a different or stale one.
- Adds a bounded authenticated retry after a public media HTTP 403, using that
  exact verified browser profile.
- Preserves the V3.0.7 Unicode-safe worker transport fix.
- Improves media-access diagnostics so the Activity Log states the precise
  reason a video was refused.
- Retains automatic updater handoff, startup confirmation, and rollback.

Some YouTube requests may still require the optional PO Token helper, which is
installed separately and is not bundled. When a request needs a PO Token and no
helper is present, the Activity Log reports that precisely (for example
`po_token_provider_unavailable`) instead of crashing or claiming the browser
login failed. This release does not claim that every YouTube video will work.

## Update and distribution status

This 3.0.8 release is an owner-authorized bridge/test release published so an
installed V3.0.7 build can detect it, verify the manifest and SHA-256, install
it, and restart into 3.0.8 for field testing. It ships the traditional one-file
Windows updater assets that V3.0.7 can consume.

Publishing this bridge release does not change the project's general compliance
status, which remains **HOLD**, and does not represent a qualified legal review.
The compliance-gated production release path stays fail-closed and the
one-folder compliance candidate remains unpublished. See the distribution
status section below.

## Runtime and GUI migration

- Replaced PyQt6 directly with PySide6 6.11.1; no compatibility shim is used.
- Preserved the GUI, responsive layout, dialogs, workers, signals, timers,
  models, translations, shutdown, and managed-browser workflows.
- Restricted the packaged Qt surface to QtCore, QtGui, QtWidgets, Shiboken, the
  Windows/offscreen platform plugins, ICO support, modern Windows style, and
  the Qt software OpenGL fallback.
- Added bounded packaged GUI smokes for both `offscreen` and `windows` platform
  modes.

## Optional PO Token helper

- Removed `bgutil-ytdlp-pot-provider` Python, JavaScript, TypeScript, npm,
  source-map, canvas, and native files from the Neural Extractor EXE.
- Removed all in-process imports and registrations of the GPL provider.
- Added an optional, separately installed and separately versioned helper with
  a narrow JSON protocol over standard input/output.
- Helper packages are manually installed; Neural Extractor does not silently
  download or install one.
- Tokens and binding data are sent only over standard input, never in process
  arguments or logs. Calls have size limits, timeouts, cancellation, redaction,
  and process-tree cleanup.
- Normal downloads continue when the helper is absent or fails.

This process boundary is stronger technical separation. It is not a legal
determination that Neural Extractor and the GPL helper are separate works. The
helper and main distribution both remain subject to qualified review.

## Native runtime correction

- Removed the canvas/MSYS2 libffi copy from the main EXE.
- Pinned the CPython 3.12.9 `_ctypes.pyd` and its compatible libffi 3.4.2
  `libffi-8.dll` by exact SHA-256.
- Added packaged ctypes callback and loaded-DLL-path verification to prevent
  accidental root-level shadowing.
- Disabled UPX to keep audited native bytes stable.

## Download and reliability behavior

- The queue uses the exact browser provider (managed Chrome or Firefox) that
  most recently completed verification.
- Active-provider state is updated atomically and cleared only for the matching
  disconnected session.
- HTTP 403 recovery remains phase-aware and bounded: a public attempt, one
  clean public retry, the exact recent verified provider once for a proven
  media 403, and at most one supported PO Token provider attempt through the
  external helper when enforcement signals match.
- The helper requests `mweb` GVS tokens with automatic/video-bound token
  fetching. Manual or copied PO Tokens are not accepted. The HTTP/listener
  provider is not bundled or loaded.
- Format metadata survives failed media transfer, preserving exact format and
  image/storyboard diagnostics.
- Unicode-safe worker framing, cancellation, timeout, updater/rollback, Mix,
  playlist, subtitle, thumbnail, Node, FFmpeg, and EJS behavior are retained.

A PO Token does not guarantee access and does not bypass account permissions,
age or region restrictions, IP reputation controls, or platform policy. An
authenticated helper attempt uses the managed session needed for the requested
video; users retain the account and platform policy risks.

Stable diagnostic categories remain:

- `verified_provider_not_applied`
- `verified_session_media_403`
- `po_token_provider_unavailable`
- `po_token_fetch_failed`
- `po_token_media_403`
- `only_sabr_or_image_formats`
- `media_access_rejected_after_authentication`
